GET /products?q=widget' HTTP/1.1
HTTP/1.1 200 OK — {"results":[ {"name":"widget"} ]}
↳ no SQL error · result unchanged
Escalate — q=widget' OR '1'='1
Nothing to chase — the parameter is bound. Move on.
Correct call — nothing to exploit here
No error, no change in the result: the value is bound to a placeholder, so it can only ever be data. A real tester reads that and walks — chasing OR 1=1 here only burns time it'll never reward.

Other platforms hand you the bug. Here you decide if there even is one — and "it's safe, leave it" is a winning answer.
